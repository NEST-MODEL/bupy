# Безопасность

## Данные пользователей

Изоляция по владельцу обеспечивается **Firestore Security Rules** (`firebase/firestore.rules`), а не проверками на фронтенде — фронтенд может быть обойдён, правила на сервере Firebase — нет. Подробности структуры и правил — в `FIREBASE.md`.

## Ключи и секреты

- **Firebase Web config** (`VITE_FIREBASE_*`) — публичный по дизайну самого Firebase, безопасность обеспечивают Security Rules, а не секретность этого конфига. Хранится в GitHub Actions Variables (не Secrets) осознанно.
- **Gemini API ключ** — чувствительный, привязан к личной бесплатной квоте. НЕ встроен в сборку. Каждый пользователь вставляет свой ключ в Профиле, ключ хранится только в `localStorage` его браузера. Подробности и актуальные шаги — в `GEMINI_SETUP.md`.
- **Service account / приватные ключи Firebase** — нигде в этом проекте не используются и не должны использоваться (фронтенд не должен иметь доступ к ним). `.gitignore` блокирует случайные `*service-account*.json`.

## Аутентификация

Email/Password через Firebase Auth. Сброс пароля не раскрывает, существует ли аккаунт с данным email (см. `ResetPassword.tsx`).

## Фото и документы

- Фото питомца хранится как сжатое превью (data URL) прямо в документе Firestore, с ограничением размера в правилах.
- Фото ветпаспорта для OCR никогда не сохраняется — обрабатывается локально в браузере и остаётся только в памяти вкладки. Подробнее — `OCR.md`.
- Firebase Storage в проекте не используется вовсе (требует платный тариф Blaze) — см. `COST_CONTROL.md`.

## Известные ограничения MVP

- Удаление питомца не удаляет каскадно его подколлекции (вакцинации, лекарства, события) — см. `FIREBASE.md`.
- Удаление аккаунта (`Profile → Удалить аккаунт`) удаляет запись Firebase Auth и документ `users/{uid}`, но не проходит по подколлекциям питомцев — пользователь предупреждён об этом в диалоге подтверждения.
