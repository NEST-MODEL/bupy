# Контроль расходов

Цель: **никогда не платить и не привязывать карту.**

## Используемые сервисы (тариф Spark)

| Сервис | Использование | Замечание |
|---|---|---|
| Firebase Authentication | Email/Password | Бесплатно. Не включайте телефонную (SMS) авторизацию — она платная. |
| Cloud Firestore | Данные пользователей | Бесплатная суточная квота: 50 000 чтений, 20 000 записей, 20 000 удалений, 1 ГиБ хранения (актуальные цифры смотрите на странице Firebase Pricing). |
| Firebase Hosting | Необязательно | Бесплатный лимит Spark. Альтернативы: Cloudflare Pages, GitHub Pages. |

На Spark при исчерпании квоты операции просто начинают отклоняться до следующих суток — автоматических списаний нет, потому что нет привязанной карты.

## Что расходует квоту Firestore

- Каждый документ в результате запроса = 1 чтение (список из 50 записей = 50 чтений).
- Открытие страницы с realtime-подпиской перечитывает данные при каждом подключении.
- Правила с `get()`/`exists()` добавляют чтения — поэтому в наших правилах их нет.
- Офлайн-кеш уменьшает повторные чтения.

## Как не превысить квоту

- Загружать данные питомца по требованию, а не подписываться на все коллекции сразу.
- Использовать `limit()` и пагинацию для длинных историй.
- Realtime-слушатели — только там, где нужно живое обновление.
- Хранить фото питомца в сжатом виде (≤ ~60 КБ) — документ Firestore не должен разрастаться.
- Следить за Usage в Firebase Console → Firestore → Usage.

## Что отключено или изменено из-за возможной оплаты

- **Cloud Storage for Firebase** — требует Blaze с 3 февраля 2026. Не используется.
- **Cloud Functions** — требуют Blaze. Не используются; напоминания локальные.
- **Платные Google Maps/OCR/SMS/email/AI API** — не используются.

## Правило на будущее

Если в консоли Firebase появится предложение «Upgrade to Blaze» ради какой-либо функции — отказаться и упростить/убрать функцию.
