# OCR ветеринарного паспорта

## Как работает

1. Пользователь фотографирует или загружает разворот паспорта на странице «Здоровье → значок скана».
2. Фото распознаётся **прямо в браузере** через [Tesseract.js](https://github.com/naptha/tesseract.js) (WASM), язык `rus+eng`. Никакие сторонние платные OCR API не используются, фото никуда не отправляется на сервер.
3. Первый запуск скачивает языковые данные и WASM-движок с публичного CDN (jsDelivr/unpkg, используется самим tesseract.js по умолчанию) — это разово и бесплатно, дальше браузер кеширует файлы.
4. Распознанный текст проходит через простой эвристический парсер (`src/utils/passportParser.ts`): ищет 15-значный номер микрочипа, строки с датой рождения, породой и строки, похожие на записи о вакцинации (известные названия вакцин или слово «вакцин»/«vaccin» + дата рядом).
5. Все найденные поля показываются пользователю **для проверки и редактирования** — ничего не сохраняется автоматически. Если что-то не распознано, поле остаётся пустым с подсказкой ввести вручную.
6. Только после нажатия «Сохранить» данные попадают в Firestore: пустые поля профиля питомца заполняются (существующие значения не перезаписываются), для каждой найденной вакцинации создаётся отдельная запись.
7. Фото паспорта **не сохраняется** ни в Firestore, ни в Storage — оно держится в памяти браузера (`URL.createObjectURL`) до момента, пока пользователь не уйдёт со страницы или не нажмёт «Удалить фото». Firebase Storage в проекте не используется вовсе (см. `COST_CONTROL.md`).

## Ограничения

- Качество распознавания сильно зависит от освещения, ракурса и почерка в паспорте — рукописный текст распознаётся хуже печатного.
- Парсер эвристический: он не «понимает» паспорт, а ищет знакомые паттерны. Разные типы бланков паспортов могут давать разное качество — отсюда обязательный шаг проверки перед сохранением.
- Для больших фото распознавание может занять 10–30 секунд на слабых устройствах — это ожидаемо, прогресс показывается в процентах.

## Обновление: распознавание через Gemini (когда доступен ключ ИИ)

Если в приложении подключён ключ Gemini (общий или личный — см. `GEMINI_SETUP.md`), скан паспорта в первую очередь отправляется на распознавание в Gemini: модель получает само фото и возвращает строго структурированный JSON (порода, дата рождения, микрочип, список вакцинаций), с явным запретом придумывать данные, которых не видно на фото. Это значительно надёжнее локального Tesseract на настоящих, «грязных» документах (печати, фото питомца на развороте, мелкий текст, отражения).

Если ключ не подключён или запрос к Gemini не удался (лимит, сеть, неверный ключ) — Bupy тихо откатывается на локальный Tesseract.js + эвристический парсер, как раньше. Пользователь не видит техническую ошибку ИИ в этом случае — просто получает результат локального OCR.

Парсер локального пути (`passportParser.ts`) дополнительно фильтрует явный мусор: если «найденное название вакцины» состоит преимущественно не из букв (типичный шум OCR на смазанном/маленьком тексте), такая запись не предлагается пользователю вовсе — лучше показать меньше, но корректных находок, чем засорять форму нечитаемым мусором.
