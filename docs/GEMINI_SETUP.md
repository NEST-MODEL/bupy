# Подключение бесплатного Gemini API к Bupy Help

## Архитектура: «принеси свой ключ» (BYOK), и почему именно так

Код Bupy лежит в **публичном** репозитории на GitHub. Любой ключ, вписанный в саму сборку (например, через GitHub Actions Variables, как ключи Firebase), окажется в собранном JS-файле — то есть будет виден каждому через «Просмотр кода страницы» или вкладку Network в браузере. Для Firebase Web config это нормально (он и должен быть публичным, безопасность обеспечивают Security Rules). Для Gemini API ключа — нет: это чувствительный ключ, привязанный к чьей-то личной бесплатной квоте.

Поэтому в Bupy каждый **пользователь сам вставляет свой ключ** в разделе «Профиль → ИИ-помощник Bupy Help». Ключ сохраняется только в `localStorage` его браузера и уходит напрямую с его устройства в Google — никогда через серверы Bupy (у Bupy нет сервера). Это же решает вопрос общей бесплатной квоты: она не делится между всеми пользователями приложения, у каждого своя.

## ⚠️ Важно: система ключей Gemini прямо сейчас меняется

По состоянию на сентябрь 2026 Google переводит Gemini API со старых «стандартных» ключей (вида `AIza...`) на новые «авторизационные» ключи, привязанные к сервисному аккаунту (вида `AQ....`). Обычные нерестрикнутые старые ключи уже отклоняются; полный переход завершается в сентябре 2026 — то есть прямо в период, когда пишется этот документ. Из-за этого:

- Точные шаги в Google AI Studio могут немного отличаться от того, что описано ниже, — интерфейс меняется.
- Проверяйте актуальную страницу **[aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey)** и официальную документацию **[ai.google.dev/gemini-api/docs/api-key](https://ai.google.dev/gemini-api/docs/api-key)** — Bupy Help ссылается именно туда.
- Код Bupy (`src/services/geminiService.ts`) отправляет ключ в заголовке `x-goog-api-key` — это текущий рекомендованный Google способ для браузерных вызовов и должен работать что со старым, что с новым форматом ключа, пока Google не изменит сам протокол.

## Как получить и подключить ключ (текущие шаги)

1. Откройте [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey), войдите с личным Google-аккаунтом.
2. Создайте ключ (Create API key). Для нового пользователя Google обычно сам создаёт бесплатный проект — платная привязка карты не требуется для бесплатного тарифа.
3. **Ограничьте ключ** (рекомендуется, а по новым правилам Google — фактически обязательно для «стандартных» ключей): в связанном проекте Google Cloud → Credentials → откройте ключ → **Application restrictions → HTTP referrers** → добавьте домен, где развёрнут Bupy (например `nest-model.github.io/*`). Также имеет смысл **API restrictions → Restrict key → Generative Language API**, чтобы ключ нельзя было использовать для других сервисов Google.
4. Скопируйте ключ, вставьте в Bupy: **Профиль → ИИ-помощник Bupy Help → Ваш ключ Gemini API → Сохранить ключ**.
5. Откройте раздел «Помощник» — появится поле для свободного вопроса.

## Бесплатные лимиты

Бесплатный тариф Gemini ограничен по числу запросов в минуту и в день (значения меняются — Google больше не публикует их на статической странице, актуальные цифры видны на вашей панели в AI Studio). При превышении лимита Bupy Help покажет сообщение о превышении и предложит повторить позже — оплата не подключается, запрос просто отклоняется до сброса лимита.

## Если что-то не работает

- **«Ключ недействителен»** — пересоздайте ключ в AI Studio, проверьте ограничение по домену (referrer) — оно должно включать домен, с которого открыт Bupy.
- **Изменился формат ключа / ошибка авторизации** — Google в процессе миграции ключей; проверьте актуальную документацию по ссылкам выше, возможно потребуется создать ключ заново в новом формате.
